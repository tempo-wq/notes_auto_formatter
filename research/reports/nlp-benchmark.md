# Smart Notes: NLP benchmark, 27 октября 2026

## Вывод

**Победитель по качеству не установлен.** Основных gold-метрик нет: независимая человеческая разметка недоступна. Ниже опубликованы реальные ресурсные замеры и диагностические silver-метрики, а не доказательство превосходства модели.

Для Fast Mode рекомендовано сохранить локальные TypeScript-правила и сначала исследовать осторожное распознавание конструкций «X — Y», исправление ложных субъектов и качество на человеческом gold. Для Deep Analysis Mode наиболее дешёвый следующий кандидат — RuleEngine + YAKE; spaCy имеет смысл проверить в минимальном окружении как источник грамматических кандидатов. Перенос Python в основной плагин на основании этого пилота не обоснован. MiniLM не рекомендуется для анализа на каждом вводе: в измеренной конфигурации затраты существенно больше, а доказанного выигрыша качества нет.

Удалены знаки ударения U+0301, сгруппированы абзацы; изменения явно указаны. См. [лицензию датасета](../datasets/LICENSE.md) и [источники](../datasets/sources.json).
- 20 укороченных определений размечены агентом прямым выбором строк и проверкой границ, независимо от выдачи адаптеров. Статус silver; 6 тестовых примеров. Отдельно 13 оригинальных challenge-примеров с явными маркерами, NONE, Markdown, математикой и составными терминами. Они не являются цитатами из внешних источников.
- 98 исходных фрагментов остаются unverified: пустые annotations не означают отрицательные примеры. Полноценного gold subset нет. Нельзя выдавать агентскую проверку за независимую человеческую разметку.
- Смещения: Unicode code points Python, полуоткрытые [start,end). Для TypeScript-baseline выполняется перевод из UTF-16; тест с emoji проходит. В каждой аннотации сохранена ожидаемая подстрока.
- На test не подбирались параметры. Параметры исследовательские: top 3/5 для YAKE, окна 2/4 для TextRank и фиксированные лимиты других методов. Score-пороги YAKE отдельно не оптимизировались.

## Конфигурации и лицензии

- Baseline: настоящий RuleEngine из плагина, сегментация и resolver, Markdown-парсер CodeMirror через постоянный Node-процесс. Правила в стабильном исправлении не менялись. Измерения включают IPC и парсинг, поэтому не сравниваются напрямую с прежним микробенчмарком только RuleEngine.
- YAKE 0.4.8: русский язык, n=3, top=3 или 5, dedupLim=.9. Лицензия пакета LGPLv3; [официальный репозиторий](https://github.com/INESCTEC/yake). Его код не включён в плагин.
- TextRank: собственный экспериментальный граф совместной встречаемости, окна 2/4, PageRank damping .85, NetworkX 3.7 (BSD-3-Clause), сборка фраз из соседних слов. Это один простой вариант, не оценка всех графовых методов.
- pymorphy3 2.0.6 (MIT) и словарь ru 2.4.417150.4580142 (MIT): вспомогательная лемматизация перед YAKE с обратным отображением диапазонов, не самостоятельный семантический классификатор.
- spaCy 3.8.7 + ru_core_news_sm 3.8.0 (MIT): зависимости nsubj, amod, nmod, compound, flat; модель обучена на новостях. Извлекаются модифицированные именные группы и подлежащие именных определений, не все существительные. NER выключен. [Документация](https://spacy.io/models/ru).
- Sentence Transformers 5.1.2 + paraphrase-multilingual-MiniLM-L12-v2: Apache 2.0, CPU fp32, max_seq_length=128, revision e8f8c211226b894fcb81acc59f3b34ba3efd5f42. [Карточка модели](https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2). Нет LLM, обучения или дообучения.
- Кандидаты для эмбеддингов: до 64 частотных regex n-грамм, затем контекстный centroid + MMR (.7/.3), top5. Контекст разделён на 120-токенные окна, максимум 256. В тройном гибриде кандидаты генерирует spaCy. Генерация кандидатов и лимиты могут определять качество сильнее самой модели.
- Вторая embedding-модель не скачивалась: без проверенного gold дополнительные веса и конфигурации пока не обоснованы. Выводы относятся только к одной модели и этому способу ранжирования.

Всего шесть тестовых исходных документов; интервалы пересекаются и не учитывают ошибки silver-разметки. Нулевой F1 baseline объясняется, в частности, преобладанием конструкций «X — Y», которых текущие правила сознательно не покрывают. Это не оценка качества всех учебных заметок. Partial overlap допускает любое непустое пересечение при взаимно-однозначном matching и может завышать полезность широких диапазонов.

Macro усредняется по категориям с определённым F1, не подставляя 1 для пустых категорий. Статистические/embedding-компоненты не обязаны распознавать IMPORTANT/EXAMPLE; межметодные выводы по полной таксономии недопустимы. DEFINITION для тела определения в этих прототипах фактически не реализован; это отдельный пробел.

## Производительность

Оборудование: Apple M5, 16 GiB RAM; macOS-26.5.2-arm64-arm-64bit; Python 3.12.14. CPU, один поток torch/BLAS, GPU/MPS не используются. Все подходы выполнены на этом компьютере, каждый в отдельном процессе.

Время инициализации — медиана трёх fresh-process запусков; файловые кэши ОС не очищались. Отдельно записан первый inference. Для устойчивой скорости: два прогрева, пять повторов. Поэтому p95 — максимум из пяти, оценка неточна; сырые выборки сохранены. RSS — сумма Python/Node с выборкой 10 мс, включает runtime, модель и прогрев, а не только результаты. Это **не** задержка интерфейса или память плагина внутри Obsidian.

Существенный конфаундер: общий pinned Python environment содержит torch. spaCy/Thinc может обнаруживать и импортировать optional frameworks. Поэтому измеренная RSS spaCy — свойство этого окружения, не минимальный расход spaCy в отдельном лёгком окружении. Перед интеграцией нужен отдельный замер minimal-dependency runtime. Сумма RSS процессов может дважды учитывать общие страницы, а короткие пики короче 10 мс могут быть пропущены.

## Удачные и ложные выделения

- Для «Интеграл это обобщение суммы.» baseline выделяет «Интеграл» и не меняет строку; при удалении «это» подсветка снимается.
- Конструкция «Обсудим это после занятия.» — отрицательный контроль, но простые правила могут принять глагол «Обсудим» за термин. Морфологическая проверка субъекта или более осторожная грамматика — конкретная исследовательская задача.
- В корпусе естественные определения через тире часто пропускаются baseline. Добавлять такую конструкцию следует отдельным изменением с отрицательными тестами, не в исправление lifecycle.
- Ниже несколько фактических выдач на одном тестовом определении; полный список находится в predictions-*.jsonl:

> Рекурсия — определение, описание, изображение какого-либо объекта или процесса внутри самого этого объекта или процесса, то есть ситуация, когда объект является частью самого себя.

- **baseline**: (нет выделений)
- **yake3**: изображение какого-либо объекта [KEY_TERM]; объект является частью [KEY_TERM]; изображение какого-либо [KEY_TERM]
- **yake_morph**: изображение какого-либо объекта [KEY_TERM]; объект является частью [KEY_TERM]; изображение какого-либо [KEY_TERM]; является частью [KEY_TERM]; процесса внутри [KEY_TERM]
- **spacy**: Рекурсия [DEFINITION_TERM]; процесса внутри самого этого объекта [KEY_TERM]
- **embeddings**: Рекурсия — определение [KEY_TERM]; Рекурсия — определение, описание [KEY_TERM]; объект является частью [KEY_TERM]; определение, описание, изображение [KEY_TERM]; процесса внутри [KEY_TERM]
- **rule_spacy_embeddings**: Рекурсия [KEY_TERM]; процесса внутри самого этого объекта [KEY_TERM]

Семантически близкая фраза не обязательно является учебным термином. Тема раздела здесь аппроксимируется окнами самого фрагмента; эксперимента с авторским заголовком реального раздела и поиском повторений между заметками не проводилось.

## Гибриды и решение

Запущены все шесть запрошенных комбинаций: правила+YAKE, правила+TextRank, правила+spaCy, правила+эмбеддинги, YAKE+pymorphy3, правила+spaCy+эмбеддинги. Простое объединение не гарантирует прироста: семантические кандидаты создают лишние выделения, а разрешение пересечений может подавлять полезный термин. По независимому качеству победителя нет.

1. Fast Mode: оставить правила и инкрементальный CodeMirror lifecycle; не добавлять Python/torch в обработчик ввода. Исправленный запуск старых заметок уже опубликован отдельно.
2. Собрать человеческий gold минимум на нескольких десятках документов, включить реалистичные конспекты без маркеров и полную разметку KEY_TERM. Сохранить source-disjoint test, оценить точность и плотность подсветки; не настраивать пороги по этому пилотному test.
3. В отдельном PR исследовать ограниченные конструкции «X — Y» и отсеивание глагольных ложных субъектов. Это может дать более дешёвое улучшение, чем внешняя модель.
4. Deep Analysis Mode: сначала сравнить правила+лёгкое статистическое ранжирование и spaCy-кандидаты в минимальном окружении. Нужен явный запуск, preview предложений и отмена заданий. Контракт кандидатов прежний; исходный документ остаётся read-only.
5. MiniLM отложить до появления подтверждённой задачи контекстного ранжирования с выигрышем качества. Даже замена модели не исправит слабую генерацию кандидатов. Перед любой интеграцией проверить лицензии зависимостей и транспорт локального процесса отдельно.

## Ограничения и воспроизводимость

Нет независимого gold, репрезентативной разметки учебной важности, всех видов формул в корпусе, полного KEY_TERM gold, системного измерения энергопотребления и интегрированного NLP в Obsidian. Короткие предложения/абзацы представлены silver/challenge и размером 100 слов; отдельной p95-таблицы для каждого предложения корпуса нет. Конфигурации прототипов ограничены и не настроены на максимальное качество. Источник Википедия отличается от реальных конспектов. Точная конфигурация моделей, seed, lock-файл Python и хэши датасета сохранены. Инструкции: [research README](../README.md).
