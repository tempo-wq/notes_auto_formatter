# Smart Notes v0.1 — Obsidian MVP

Локальная подсветка явных конструкций русского учебного текста в редакторе Obsidian. Плагин не переписывает заметки, не отправляет текст в сеть и не использует модели.

## Установка

1. Скопируйте `main.js`, `manifest.json`, `styles.css` из `release/smart-notes/` в `<ваше хранилище>/.obsidian/plugins/smart-notes/`.
2. В Obsidian откройте настройки → Сторонние плагины и включите Smart Notes. Используйте только доверенные плагины.
3. Откройте заметку в редакторе (Source mode или Live Preview). Reading view не поддерживается.

Пример:

```text
Производная это предел отношения приращения функции к приращению аргумента.
Важно: сохранять исходный текст.
Например, производная постоянной равна нулю.
Будем использовать термин «градиентный спуск».
```

После паузы подсветятся термин определения, важное утверждение, пример и явно названный термин.

## Настройки

| Профиль | Пауза | Лимит строки |
|---|---:|---:|
| Economy | 1200 мс | 500 символов |
| Balanced | 500 мс | 2000 символов |
| Active | 200 мс | 4000 символов |

Все категории можно отключить отдельно. Диагностика показывает число анализов, попаданий кэша и пропусков; она не содержит текст заметок, не сохраняется и не отправляется в сеть. Пропуски считаются по попыткам обработки, а не по уникальным строкам.

## Ограничения

- Это правила распознавания явных конструкций, а не полноценное понимание смысла.
- Анализ ленивый: видимые строки обрабатываются после паузы; при прокрутке анализируется новая область. Скрытые участки не сканируются заранее.
- Каждая физическая строка обрабатывается независимо. Определение, разбитое переносом строки, может не распознаться.
- Строки длиннее лимита профиля пропускаются целиком: текст не обрезается, предположительные результаты не выдаются. Это консервативный вариант разрешённой стратегии пропуска; диагностический счётчик показывает такие случаи.
- Заголовки не считаются терминами автоматически. KEY_TERM использует явное именование в кавычках; общего словаря по хранилищу нет.
- Код, формулы, ссылки, HTML, frontmatter и существующее оформление защищаются. Если Markdown ещё не разобран, подсветка откладывается до обновления дерева разбора или следующего события редактора.
- Неоднозначные предложения пропускаются. Сокращения русского языка обрабатываются ограниченным набором правил.
- Обычные правки инвалидируют изменённые строки. Изменения Markdown-разделителей сбрасывают результаты консервативно.
- После открытия и прокрутки возможна пауза до появления выделений. При IME-композиции анализ откладывается.
- Минимальная заявленная версия Obsidian: 1.8.7; совместимость с ней требует отдельной проверки. Разработка использует актуальные определения API, закреплённые lock-файлом.

## Разработка

Нужен Node.js 22+ и pnpm.

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm test
pnpm bench
```

Если политика pnpm блокирует build scripts, esbuild использует установленный платформенный пакет. Наличие рабочего esbuild проверяется сборкой. Сетевой доступ нужен только при установке зависимостей разработчика.

Сборка: `main.js`. Готовые файлы установки: `release/smart-notes/`.

`BENCHMARKS.json` содержит реальные синтетические измерения, характеристики машины и область измерения. Они не включают Markdown-парсер, интерфейс Obsidian, память или энергопотребление. Проверка интерфейса описана отдельно в `VALIDATION.md`.

## Архитектура

`main.ts` регистрирует настройки и расширение. `editorExtension.ts` содержит наблюдение, очередь с debounce, состояние диапазонов и отрисовку. `MarkdownContext.ts` выделяет защищённые участки по дереву CodeMirror и дополнительным консервативным проверкам. Чистые `TextSegmenter`, `RuleEngine`, `HighlightResolver` не зависят от Obsidian.

Координаты: UTF-16, полуоткрытые диапазоны `[from, to)`. У правил они локальные, у редактора абсолютные. Уверенность — вес эвристики, не вероятность. Приоритет: definition-term → important → example → key-term; пересекающийся кандидат меньшего приоритета целиком отклоняется.

У каждого редактора свой планировщик и кэш до 128 строк. Храним не более 2048 результатов в окрестности последнего обработанного участка. Результаты проверяются по ревизии документа, поколению задания и идентификатору открытого файла. При смене заметки очищается кэш. Все таймеры отменяются при уничтожении расширения. Единственные сохраняемые данные плагина — настройки.

## Дальнейшее развитие

v0.2: улучшить морфологию и составные термины на размеченном корпусе, сохраняя контракт кандидатов. Добавлять Python или иной процесс только при доказанной необходимости.

## Статус публикации

Это MVP для тестирования, не стабильный релиз. Сборка и 40 автоматических тестов проходят. В Obsidian 1.14.4 проверены ввод, удаление, Undo/Redo и настройки. Визуальная перепроверка нового стиля IMPORTANT, светлая тема, Source mode и прокрутка длинных заметок ещё не завершены; подробности в `VALIDATION.md`.

Лицензия использования пока не выбрана владельцем проекта.
