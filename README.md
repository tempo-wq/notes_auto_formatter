# Smart Notes v0.2 — Advanced NLP

Локальная подсветка русских учебных конспектов в редакторе Obsidian. Плагин сохраняет Markdown без изменений и работает без интернета, Python, облачных API и скачиваемых моделей. Расширенный анализ — ограниченные языковые эвристики на TypeScript; полноценного понимания смысла и морфологического разбора нет.

## Установка и обновление

1. Скопируйте **три файла** из `release/smart-notes/`: `main.js`, `manifest.json`, `styles.css` в `<хранилище>/.obsidian/plugins/smart-notes/`.
2. При обновлении сначала выключите Smart Notes, замените файлы и включите его снова. Простое обновление списка плагинов не гарантирует перезапуск загруженного кода.
3. Откройте существующую заметку в Source mode или Live Preview. Reading view не поддерживается. В каждом хранилище плагин устанавливается и включается отдельно.
4. После паузы сначала появятся быстрые выделения, затем расширенные. Изменять старую заметку для запуска не требуется. Команда `Smart Notes: Reanalyze current note` повторяет обработку текущей заметки.

Пример:

```text
Градиентный спуск — алгоритм оптимизации.
Градиентный спуск изменяет параметры модели.

Под коэффициентом обучения понимают размер шага.
Функция потерь определяется как мера ошибки.
Кинетическая энергия является разновидностью энергии.
Важно: сохранять исходный текст.
Допустим, что скорость постоянна.
```

Выделяется термин определения, а не всё его тело. Повторный составной термин может подчёркиваться, если непосредственно предыдущая строка содержит его определение. Произвольные существительные не выделяются. Явные перечисления проявлений/компонентов дают максимум три дополнительных ключевых фразы на строку. Важность и примеры определяются по явным вводным маркерам.

## Режимы

| Глубина | Поведение |
|---|---|
| Rules Only | Только быстрые правила, расширенный движок не инициализируется |
| Automatic, по умолчанию | Расширенный анализ после завершения предложения/перечисления и паузы |
| Advanced | Также рассматривает незавершённую строку после паузы; сложные случаи по-прежнему может пропускать |

| Профиль | Быстрый debounce | Дополнительная пауза Advanced | Лимит физической строки |
|---|---:|---:|---:|
| Economy | 1200 мс | 1200 мс | 500 UTF-16 символов |
| Balanced | 500 мс | 500 мс | 2000 |
| Active | 200 мс | 400 мс | 4000 |

Каждую категорию можно выключить отдельно. Диагностика содержит только счётчики, не тексты заметок; сохраняются только настройки. Для полного отключения используйте переключатель Smart Notes в сторонних плагинах.

## Архитектура и ресурсы

`EditorObserver / debounce → TextSegmenter → NLPManager → RuleEngine + AdvancedEngine → HighlightResolver → Decorations`.

Один лениво создаваемый Advanced Engine на экземпляр плагина, без весов и внешнего процесса. Координаты — UTF-16 `[from,to)` относительно запроса; контекст не включён в них. Перед применением проверяются ревизия, поколение задания и файл. Правка, смена файла и закрытие редактора отменяют старые задания.

Видимые строки имеют приоритет; конечный фоновый проход рассматривает до 64 соседних строк с каждой стороны в пределах ±20 000 символов. Весь файл не сканируется после каждой правки: остальное обрабатывается по мере прокрутки. На редактор — кэш до 128 записей и до 2048 диапазонов; очередь максимум 256 видимых + 128 соседних строк. Между заданиями управление возвращается редактору. Постоянного опроса нет.

Устанавливаемый пакет около 19 KB, скачиваемых моделей 0 байт. Синтетический полный проход на Apple M5: p95 около 0,99 мс / 9,58 мс / 90,27 мс для 1k/10k/100k слов. Это измерения анализатора в Node, **не** задержка ввода в Obsidian. Память процесса Node около 82 MiB на пике, включая runtime; её нельзя приписывать плагину. Подробные методика, CPU и ограничения: [отчёт v0.2](docs/v02-validation.md).

## Качество и ограничения

На неизменной агентской test-разметке: TERM F1 v0.1 = .075, v0.2 Automatic = .262; TP 2 → 8, FP 2 → 4, FN 47 → 41. Это диагностика на 20 фрагментах шести источников, **не независимый gold** и не гарантия качества произвольных конспектов. Семантическая важность без маркеров остаётся нерешённой. Исследование не доказало превосходства Python/embedding-моделей; решение описано в [ADR](docs/adr/002-local-advanced-analysis.md).

- Русская морфология поддерживается только шаблонами конструкций и точными словоформами повторений. Неоднозначные термины, определения через несколько строк и местоименные связи часто пропускаются.
- Длинные физические строки пропускаются целиком. Перенос изображения строки редактором не делит физическую строку.
- Код, формулы, frontmatter, ссылки, HTML и пользовательское оформление защищаются деревом Markdown и дополнительными проверками. Неразобранные участки пропускаются; парсер продвигается с ограниченным бюджетом. Повторите анализ командой или прокруткой при необходимости.
- Проверен настольный Obsidian 1.14.5 на macOS; мобильные устройства и минимальная заявленная версия 1.8.7 отдельно не проверены.
- Нет редактирования Markdown, графа понятий, поиска по всему хранилищу, полноценного семантического ранжирования, Python/ONNX/LLM-режима. Они остаются возможными направлениями исследования.

## Откат

Выключите плагин и замените те же три файла версией из [v0.1.1-stable](https://github.com/tempo-wq/notes_auto_formatter/releases/tag/v0.1.1-stable), затем включите. Заметки не мигрируют и не требуют восстановления. Дополнительная настройка `nlpMode` игнорируется старой версией.

## Разработка

Node.js 24, pnpm 11.25.0; зависимости закреплены `pnpm-lock.yaml`.

```sh
pnpm install --frozen-lockfile
pnpm test
pnpm build
pnpm package
pnpm bench:v02
node scripts/prepare-v02.mjs
NODE_BINARY=$(command -v node) research/.venv/bin/python research/evaluate_v02.py
```

Отдельного линтера нет; сборка включает строгую проверку TypeScript. Исследовательское Python-окружение нужно только для воспроизведения оценок, не пользователю плагина. Сохранены исходные отчёты и исследования в `research/`; их лицензии и атрибуция указаны отдельно. Лицензия исходного кода пока не выбрана владельцем проекта.
